# 产品目标与防偏航基线

复核日期：2026-09-05。依据：本项目近期会话、持续需求澄清、最近八次提交及公开验证记录。
本文是需求基线，不新增产品承诺；实现状态以[状态台账](status.md)和对应证据为准。

## 用户真正要的结果

> 把已有 Agent 方便地接入企业微信，提供快速、忠实、稳定的双向通信中间层。
> Gateway 不负责 Agent 如何思考；不同 Kernel 通过少量 Adapter 接入同一条链路。

| 原始要求 / 澄清                                              | 对项目的约束                                                                         | 当前对应与差距                                                                                        |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| “重点是中间层，快速方便稳定是特色”                           | 先解决接入成本、首回执、流式、顺序、投递、恢复和排障                                 | Core/Transport/SQLite/观测已有实现；不能把 Agent 首文本时间或健康状态当成链路 SLA                     |
| Codex 只是测试案例，还要支持 Pi、Kimi、OpenClaw、Claude Code | Kernel 专属状态/认证/协议在 Adapter，Core 不写厂商分支                               | 四类参考接入有历史真实证据；Claude Code 仍缺自有凭据成功验收；外部 SDK 不等于任意 harness 零配置      |
| 双身份不可接受；优先用企业微信官方工具                       | 正式收发只有 Bot 身份，官方 SDK 承担企微协议；CLI 是可选办公工具                     | 保留单 Bot 身份和进程所有权；真人客户端自动化仅用于用户侧测试，不成为产品收发通道                     |
| 不同模态都能交互；支持可变消息、流式与必要确认               | 原样保留内容/媒体/引用；显式状态和交互才投影到 UI                                    | 卡片不是每条回复的尾巴；不展示隐藏推理；视频运输与视频理解分开验证；原生 video/quote 回调仍缺真实证据 |
| 开源后别人能看懂、方便上手、有接地气的案例                   | README 有真实效果、明确前置条件和最短步骤；代码入口能独立复现                        | 已有真实 GIF、双语指南和使用配方；本轮增加无凭据全新安装与 CLI 入口门，尚非新用户完整 Bot 首聊认证    |
| 已授权测试，自动化闭环，不要反复让我代发；不能虚报完成       | 在既定私聊/测试群范围自主执行、记录可见结果；区分实现、fixture、真实上游与长时稳定性 | 不重复索要已有授权；新目标或破坏性动作不从“自动闭环”推导授权。不能制造第二条 Bot 连接抢占服务         |

## 近期工作的诚实复盘

- **方向吻合：** 上手生成器、无凭据 demo、独立 Agent 检查、Bot 单实例保护、投递状态诊断和故障脱敏，
  都直接服务于“方便、快速定位、稳定”，不要求把模型或工作流并入 Gateway。
- **过去有偏差：** 默认追加卡片、围绕样式进行多轮人工往返、重复索要已给出的测试授权，
  以及未区分原生视频与普通 MP4/file 的完成声明。这些不能仅因后来有修复而从复盘中消失。
- **现在仍有风险：** README/调研/验收器越做越多，却没有增加真实证据；或者从竞品学到 HTTP/多语言接口后
  扩成 Agent 平台。文档和测试工具只是辅助产物，不能代替用户可用的链路。
- **本轮取舍：** 不继续调研、不加新卡片或模型入口。验证公开命令在无项目缓存、无 Bot/模型凭据的安装环境
  可以运行，并在缺前置条件时明确失败。这是“方便接入”的独立主线切片，不宣称关闭可靠性证据尾项。

## 后续执行门

每个增量必须能回答：改善哪一个已明确的用户结果？改哪一层？怎样独立复现？还不能证明什么？

1. 正式服务已知缺陷优先；不得为测试抢占 Bot 或污染配置。
2. 保持真实 video/quote、宿主断网/上传失败恢复、Linux 24h 的证据缺口可见。
   重试相同客户端入口不会凭空产生缺失的上游 frame；仅有 fixture 时保持未认证。
3. 当前直接推进新环境接入门；随后针对明确安装失败做修正，不先开发未经验证的一键安装产品。
4. 只有现有 Adapter 接入出现具体障碍时，才推进远程/跨语言协议 ADR；目前不是必须交付的新平台。
5. 传播素材基于真实案例与可复现问题解决，不以 Star 数、模型数、卡片数作为工程完成标准。

**明确不做：** 模型管理/充值代理、Agent 人格/记忆产品、自然语言自动路由、跨 Kernel 任务迁移、
真人身份兜底、默认回复装饰卡、大而全的办公助手。
已有会话续接是 Gateway 管理的会话，不是接管任意桌面任务或迁移其他 harness 历史。
