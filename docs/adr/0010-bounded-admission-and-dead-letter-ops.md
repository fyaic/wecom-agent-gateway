# ADR 0010：Gateway 采用有界接入和受限死信运维

- 状态：已接受
- 日期：2026-08-21

## 决策

Gateway 在 ACL 通过后、入站持久化前申请容量。默认全局最多 100 条 active/queued 入站、单会话
最多 10 条、同时最多 8 个 Agent run。前两项超限时直接拒绝，第三项使用公平等待队列；同一会话
原有串行语义保持不变。

过载拒绝不创建 Agent turn、不写入 inbound 表，也不自动生成 Bot 回复。自动回复会为每条攻击
流量新增 outbox 和网络负载，破坏背压目的。系统只发出不含任何 ID 的 `gateway_backpressure`
事件，交由部署告警和容量策略处理。

## 死信操作

本地管理命令提供：

- 五种 Outbox 状态的聚合计数，不显示目标、正文或内部 ID；
- 带显式确认门和 1–100 条上限的文本死信重排；
- 只选择最终 `reply` 与 `proactive`，排除 partial 与媒体；
- 尝试次数归零、状态恢复 pending，实际发送仍由正常 worker 认领；
- 历史失败 journal 不删除。

媒体死信进入终态时 artifact 已清理，不能原地重放。主动文本重排仍可能产生重复消息，因此命令
本身是操作员明确授权的外部副作用，不能由健康检查、自动启动或 Agent 自行触发。

## 后续

当前是单实例进程内 admission control。多实例需要共享队列长度/租约数据库或外部 broker；还需
补充按租户配额、基于延迟的自适应并发、告警阈值和可审计的死信审批界面。
