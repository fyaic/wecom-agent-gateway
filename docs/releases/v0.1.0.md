# v0.1.0 — Public Preview

`wecom-agent-gateway` is a runtime-neutral IM gateway that connects one WeCom
Bot identity to a pluggable Agent Kernel through a stable Runtime Contract.
This first Public Preview establishes the transport, reliability, security, and
Adapter boundaries; it does not promise a stable v1 API or production SLA.

## Highlights

- Official `@wecom/aibot-node-sdk` transport for WebSocket authentication,
  heartbeat/reconnect, mutable streaming replies, media download/decryption,
  and proactive push.
- Runtime Contract v1 with reference adapters for Codex, ACP/Kimi Code,
  OpenClaw, and Pi Agent, plus a validated external Adapter SDK and template.
- Direct and group conversations, scoped fail-closed ACLs, per-conversation
  ordering, bounded cross-conversation concurrency, session recovery, and
  explicit capability negotiation.
- Runtime types for text, image, file, and video-binary input plus
  image/file/video output through a protected media spool and the official
  upload/send APIs. Runtime type support is not a claim that every client and
  Kernel combination has passed real end-to-end acceptance.
- Durable SQLite outbox with leases, retry/backoff, stream-state supersession,
  dead letters, crash recovery, and identifier-free operational metrics.
- Credential-free local proactive text/media control, durable approval prompts,
  and narrowly mapped `wecom-cli` office tools.
- Loopback liveness/readiness, privacy-safe Prometheus metrics, deployment
  Doctor, macOS LaunchAgent examples, Linux/systemd reference, and hardened
  non-root container baseline.

## Verified baseline

- 141 deterministic tests across the Runtime Contract, Gateway Core, official
  transport mapping, storage, media, control plane, observability, and adapters.
- Real WeCom acceptance for authorized direct/group text, mutable streaming,
  multi-turn recovery, images, files, MP4 binary delivery, proactive text/media,
  write approval, and managed process restart.
- Real adapter acceptance for Codex, Kimi Code ACP, OpenClaw, and Pi with GLM
  text and vision configurations where the selected model declares support.
- Isolated Linux network detach/reconnect with official SDK readiness
  degradation and re-authentication; SQLite `SIGKILL`, read-only volume, and
  bounded-capacity recovery evidence.

## Known limitations

- One Bot identity must be owned by exactly one Gateway process. Multi-instance
  ownership, distributed backpressure, and global ordering are not defined.
- A real Linux/systemd long-duration soak and host-level NIC/route/DNS outage
  remain deployment validation work; container namespace tests are not a claim
  about an entire host network stack.
- A native WeCom `msgtype=video` desktop callback has not been captured. An MP4
  sent as a regular file has real evidence through semantic classification and
  the Kernel capability gate, but video understanding has not passed. Official
  video/file frame normalization has deterministic coverage.
- Voice callbacks may expose transcription without downloadable source audio,
  depending on the official callback payload.
- Media understanding, video frame extraction, model choice, reasoning, and
  Agent tool availability belong to the selected Kernel, not Gateway Core.
- The repository includes no Bot, Kernel, model, or provider credentials and no
  hosted runtime. Operators supply and secure their own deployment environment.

## Upgrade and support

This is the first published version. Follow the root README and deployment
Doctor for setup. Report reproducible bugs through GitHub Issues and suspected
vulnerabilities through a private GitHub Security Advisory. Never attach Bot
credentials, internal IDs, employee/conversation names, message contents,
private logs, databases, or media URLs.

The release workflow publishes a reproducible `git archive` source bundle and
its SHA-256 checksum. GitHub artifact attestation binds the bundle digest to the
tag-triggered workflow and can be verified with `gh attestation verify` against
this repository. GitHub-generated source archives remain available as usual.
No local databases, logs, configuration, transcripts, or media are uploaded.
