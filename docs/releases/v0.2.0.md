# v0.2.0 — Security and Reliability Convergence

This planned Public Preview release keeps the product boundary unchanged: a
runtime-neutral WeCom Bot IM gateway with optional channel-native interaction,
not an Agent reasoning system. It consolidates security, persistence, recovery,
and release engineering learned from the real-client acceptance program.

## Highlights

- Quoted messages retain neutral context while ephemeral media URLs,
  decryption keys, and local paths are removed before persistence.
- Feedback and `enter_chat` callbacks use the same direct/group scoped ACL as
  ordinary inbound messages and never create a semantic Agent turn.
- Official SDK reconnect continues through long transient outages; repeated
  authentication failure remains bounded. Private endpoints must be
  credential-free `wss://` URLs.
- SQLite schema version 1 fails closed against unknown future schemas. Bounded
  retention removes old terminal records while preserving pending, leased,
  dead, and not-yet-resumed work.
- Codex child processes inherit a least-privilege environment. Official SDK
  payload logs and Adapter stderr are disabled by default and explicitly
  opt-in for temporary diagnostics.
- Every tag is revalidated with full CI and public-history scanning, must point
  to a commit on `main`, and uses a tag-matched release-notes file.

## Compatibility

- Runtime Contract remains version 1.
- The Gateway still runs exactly one Bot identity and one selected Kernel
  Adapter per process.
- Cards remain an optional presentation and interaction capability. Ordinary
  text, media, streaming, session, and delivery behavior does not depend on
  card support.
- Existing SQLite databases with schema version 0 are initialized to version 1
  without discarding data. Databases created by a future schema are rejected.

## Operator notes

Review the new retention, reconnect, diagnostic-log, and Adapter environment
variables in `.env.example` before upgrade. Keep raw SDK/Adapter diagnostic
logging disabled in normal operation. Back up the private data directory before
upgrading and run `pnpm doctor` plus `pnpm run ci` in the deployment checkout.

No Bot, Kernel, model, or provider credentials are shipped by this repository.
