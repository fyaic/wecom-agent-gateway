# Vitest 5 更新复核（2026-09-07）

范围：[开发工具 PR #60](https://github.com/fyaic/wecom-agent-gateway/pull/60)。
这是独立于运行时客户端更新的开发依赖提交，不改变 Bot、模型或 Transport 行为。

核对 [Vitest 5 官方发布说明](https://github.com/vitest-dev/vitest/releases/tag/v5.0.0) 的迁移风险：

- 发布包 engines 实际为 `^22.12.0 || ^24.0.0 || >=26.0.0`，并非泛化的 Node >=22。
  与运行时依赖取交集后，源码仓库采用 `^22.19.0 || ^24.0.0 || >=26.0.0`；doctor 明确拒绝
  Node 23/25，并新增 6 项版本范围回归。仍需 Linux CI 验证部署用的 Node 22。
- 不依赖已删除的 `@vitest/runner` / `@vitest/expect` 入口、旧 sequential 测试选项、浏览器测试和快照格式。
- 保持原配置与测试隔离，不为追求发布说明中的性能收益启用 `isolate: false`。
- 默认清理 mocks、未 await 异步断言更严格、定时器变化均由全量套件实际执行核对；没有放宽断言、
  新增 skip 或提高重试次数来掩盖不兼容。

本地更新 `vitest` 4.1.11 → 5.0.0 并重新生成精确锁文件后，`pnpm run ci` 通过：
37 个测试文件、343 项测试，与更新前完全一致；格式、类型和公开文件检查通过。
主审后续补齐 SDK 生命周期与 Node 版本范围回归后，37 个文件、353 项测试通过。
本仓库的 Windows 专属 skip 条件保持原样，本次 macOS 执行没有因升级新跳过测试。

这些是开发工具回归结果，不是 Agent/企业微信真实兼容证据，也不代替 Linux CI。
