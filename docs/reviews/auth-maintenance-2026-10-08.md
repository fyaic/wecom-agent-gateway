# 授权维护插件主审 · 2026-10-08

## 目标与范围

让社区用户使用自己的 Gateway Bot 和能力白名单配置可选授权维护，不依赖维护者身份。
Gateway 继续提供稳定的 Kernel 无关消息中间层；Agent 由 Adapter 插件接入，授权维护由独立运维插件接入。
本轮没有更改 Transport、消息 Core、Agent Adapter、默认卡片、CLI 现有身份或部署服务。

## 分工与主审返工

| 责任            | 实际交付                                                                         |
| --------------- | -------------------------------------------------------------------------------- |
| Keeper 子 Agent | 显式 pre-renew、完整页面观测、合法失效页数据保留、固定错误输出、配置快照摘要绑定 |
| 状态机子 Agent  | inspect/renew 契约、互斥、0600 原子状态、耐久意图、退避、跨周期预续与恢复        |
| 配置子 Agent    | 同 Bot 私有输入生成、默认关闭、防覆盖、社区指南及 setup→worker 集成测试          |
| 主 Agent        | Keeper provider、串行 worker / CLI、集成审查、独立边界检查、全量回归、文档与提交 |

审查发现并退回的关键问题：

1. 页面动作和业务验证混为一谈会导致续期成功后 intent 永不解除；拆为页面确认、业务证据两个维度，不伪造后者。
2. 用新到期时间永久去重会阻止下一次临期维护；改为至少一小时的有界抑制与下一窗口时间，测试两次临期周期。
3. Provider 检查配置后 Wrapper 重读有竞态；实际生成临时快照的同一次读取校验 canonical 路径和摘要。
4. 原 Keeper 不允许预续期可见链接导航；先 inspect 允许可见入口，pre-renew 始终强制已有正确窗口。
5. CLI / engine / Wrapper 阈值不一致；统一为 0–168 小时。

## 证据及限制

确定性测试覆盖默认关闭、配置身份不符、状态损坏、并发锁、未知副作用、pending 恢复、到期前后两个周期、
页面成功但业务未验证、原子状态、脱敏、停止 worker、重复 tick 和完整配置生成链路。
集成链路使用真实 setup、环境文件加载、Provider、engine 与文件系统状态，只替换 GUI 末端。

最终 `pnpm run ci`：**48 个测试文件 / 584 项通过**，格式、类型与公开准备检查通过。
首次全量测试 581 项通过，但公开门把恶意 URL 测试夹具中的虚构 userinfo 识别为邮箱；
改为在测试运行时构造该输入，没有放宽扫描规则。主审另补 3 项损坏 intent 回归，防止 falsy 值绕过状态校验。
真实运行 `pnpm auth:maintenance once` 在未配置时返回 `disabled` / `businessVerified:false`，未启动 GUI。

真实 GUI 续期、Gateway 同 Bot 业务探针及跨真实到期周期，本轮均未执行，不能以 fake 测试替代。
本地 Keeper 仓库本轮观察到后续文档提交，代码仍未提供任意桌面状态导航。
已有 Keeper 配置并非 Gateway Bot，本轮不复用其成功结果，不操作其授权。

Worker 默认关闭、不安装服务；检查可见授权链接并不等于自动搜索会话或导航管理后台。
机器休眠、桌面未登录、系统辅助功能权限缺失、官方授权交互改变、崩溃遗留锁都可能需要运维介入。
业务写操作不会因授权恢复自动重放。

## 后续退出条件

1. **自己的 Bot 可配置**：生成私有配置，验证 Gateway / 页面 / CLI 是同一身份，不重置其他 CLI profile。
2. **入口自动化**：从正常桌面恢复正确 Bot 权限页；错误页面不能操作，不能依赖维护者手动提前开页。
3. **真实分层验证**：一次受控页面恢复后，使用同 Bot 对白名单具体能力复探；写能力仅用专用测试对象。
4. **跨周期认证**：记录至少一次真实临期维护、复查及下一周期正常检查，无重复撤权/授权风暴。
5. **交付**：上述证据齐全再启用参考部署的常驻维护，不把可选 macOS GUI 依赖加入所有用户启动门。

目前不宣称上述真实退出条件已全部满足。
