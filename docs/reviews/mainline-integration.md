# 主线专项合并审查 — 2026-09-05

## 目标和分工

本轮按用户要求，三个独立 worktree 分别处理传输恢复、Claude Adapter 与 Linux soak；主 Agent
负责复审、追加故障测试、合并与实际客户端验收。基线为 `599053c`，不在工作树启动第二个 Bot。
主线仍是 Kernel 无关、忠实可靠的 IM 中间层：不调整推理、模型、人格或默认卡片，不扩展新 IM。

| 专项           | 实际修复                                                                    | 证据及限制                                                                                       |
| -------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 传输恢复       | 仅结构化过期 ACK 允许主动降级；拒绝错误文本中的数字误命中                   | [独立记录](delivery-closure.md)；上传、未知 ACK、重试/本地提交故障为 fake-backed，不冒充宿主断网 |
| Claude Adapter | 同会话并发所有权、取消优先、终态清理、流式与最终 session 校验               | [独立记录](claude-closure.md)；官方 SDK CLI 报未登录，未调用真实模型                             |
| Linux 验收器   | 指标未知值、采样覆盖、健康正文、服务代际、历史 dead 都 fail closed          | [独立记录](soak-closure.md)；schema v2，尚无真实 systemd 24h 报告                                |
| 主审追加       | 流式串单必须在文本投影前拒绝；真实验收必须显式指定 Adapter compatibility ID | 对应回归防止文本泄漏及旧 `.env` 引发证据误归属                                                   |

## 实际私聊基线（部署前）

主 Agent 用企业微信桌面端在已授权 Bot 私聊发送唯一测试标记，观察同一回复从状态文字变为预期短文本。
`verify:real-wecom-ingress --kind=text --conversation=direct --adapter=pi:rpc-v1` 九项检查通过，唯一入站、
会话归属、最终投递接受、无错误/积压以及 spool 清理均满足；服务 health ready，pending/leased/dead 为零。
初次未显式指定 Adapter 的检查误读 `.env` 中旧选择，未通过归属门；修正参数后通过，并修复命令默认行为。

| 层级          | 本次观测 | 起点        |
| ------------- | -------- | ----------- |
| Channel 回执  | 426ms    | 入队        |
| Kernel 首事件 | 90ms     | Adapter run |

这些是单次基线而非 SLA；首文本主要等待在 Adapter/Kernel 段，不能把最终回复称为低延迟，亦不据此改写
Agent 的思考策略。旧部署仍启用可选长任务控制卡，本轮没有认证“客户端完全无卡”；新生成配置默认关闭。
客户端旁栏有无关私聊，因此没有把原始截图、正文日志、身份或会话标识放入仓库。

## 验收和下一步

整合后完整 `pnpm run ci` 通过：37 个测试文件、334 项测试，格式、类型与公开检查均通过。PR 检查另覆盖
干净 macOS/Linux 安装。合并后的受管重载与第二次真实
私聊结果另附 PR 验收评论，避免把部署前基线称为部署后证据。

以下仍是独立未完成条件，不因本轮自动化通过而升级支持声明：

- 原生 `msgtype=video`、引用消息的真实客户端回调；桌面 MP4(file) 不替代原生视频证据。
- Claude 自有认证下的真实文本/session 及后续媒体/交互矩阵，仍为 experimental。
- 真实 Linux/systemd 部署、受控重启恢复后完整无重启 24h 窗口，以及宿主网络/上传失败恢复。
- 多实例生产语义仍未实现；本轮坚持 single-active。

优先补上述证据，不继续扩大卡片或模型功能。网络中断不能影响无关宿主工作；Linux 验收也不能另开同 Bot
并发连接。需要明确的隔离部署及所有权安排后再开展，不把缺少环境记成通过。
