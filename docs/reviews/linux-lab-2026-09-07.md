## 实测发现的正式部署问题

最初 fixture 用 `ExecStart=tsx ...`，正常 `systemctl stop` 时包装进程返回 143，服务被误标为 failed。
改为 Node 直接加载 `tsx` 后，正常停机得到 `Result=success / ExecMainStatus=0 / ActiveState=inactive`。
正式 [unit 样例](../../deploy/linux/wecom-agent-gateway.service.example) 同步改为
`__NODE_PATH__ --import tsx apps/gateway/src/index.ts`，保留 Doctor、降权、持久目录和优雅停机约束；
不以 `SuccessExitStatus=143` 掩盖退出失败。静态检查加上此不变量，fixture 还有真实 Core/SQLite 的确定性回归。
主维护者随后在同一 VM 的服务用户预检发现 `pnpm` 会尝试重新检查/安装 root 已部署依赖并因无 TTY 退出；
因此 `ExecStartPre` 也直接执行 Node + `tsx` 的 Doctor 实现，不在服务启动时用 `CI=true` 绕过目录清理门。

`systemctl start` 返回时进程可能尚未 ready，必须等待健康端点，不能把启动命令返回等同于链路准备完成。

## 可复用环境与边界

- VM 模板：[lima-lab.yaml](../../deploy/linux/lima-lab.yaml)。官方 Lima 2.2.0 + macOS VZ；
  `plain:true`、`mounts:[]`、无 SSH agent/既有公钥导入、无动态端口转发、无内置 containerd。
  使用固定 SHA512 的 Debian 官方 cloud image；没有新收费资源、宿主 sudo 或网络调整。
- [fixture](../../scripts/linux-lab-service.ts) 只加载仓库外部 Echo Adapter 与 Loopback Transport，
  不读取 Bot 凭据、不创建官方 SDK 连接；实际 Core、SQLite、健康端点与 systemd 用于部署预检。
- Docker lab 镜像只是验证工具，不替代正式镜像；[lab.Dockerfile](../../deploy/linux/lab.Dockerfile)
  的 systemd 包来自 Debian 官方源，完整 PID 1 启动仍依赖受委派、可写的容器自身 cgroup。
  [systemd 官方容器接口](https://systemd.io/CONTAINER_INTERFACE/)支持这一边界。
- [Lima plain 模式](https://lima-vm.io/docs/config/plain/)关闭便利共享功能；仍能使用受限 SSH
  与文件复制准备客体。不能通过挂载整个宿主目录来偷渡模型认证或项目数据。
- VM 已安装 Node 22.23.2、pnpm 11.8.0 和本机同版本 Pi 0.84.2。Pi 的当前包名经本机安装元数据核实为
  `@earendil-works/pi-coding-agent`；没有使用旧 scope 的安装失败冒充成功。

## 维护者操作入口

创建同配置的全新专属环境（不是日常用户快速上手要求）：

```bash
HOMEBREW_NO_AUTO_UPDATE=1 HOMEBREW_NO_INSTALL_CLEANUP=1 brew install lima
limactl create --tty=false --name wecom-gateway-lab deploy/linux/lima-lab.yaml
limactl start --tty=false wecom-gateway-lab
limactl shell --workdir=/app wecom-gateway-lab node --import tsx --eval 'console.log("tsx-loader-ready")'
```

本次将**本项目自己构建的无凭据镜像**中的 Node 工具和 `/app` 通过 tar/SSH 复制到空白 VM，
不是共享宿主目录；随后按冻结 lockfile 安装依赖。新环境需要先部署仓库和这些依赖，再执行最后一条检查。
更新代码时必须在正式验收窗口前完成安装和自检；开始 24h 后不能再更新或重启服务。

当前维护者准备的真实 unit 是 `wecom-agent-gateway.service`：`WorkingDirectory=/app`，
`HOME=/var/lib/wecom-agent-gateway`，私有配置 `/etc/wecom-agent-gateway/gateway.env`（0600 root），
Pi 配置只需进入 `/var/lib/wecom-agent-gateway/.pi/agent`（0700 gateway）。不复制整个个人目录。
固定单 Bot 所有权切换由主维护者执行；本分工只准备环境，真实 unit 保持 inactive/disabled。

```bash
# 只停止本项目 fixture；真实 Bot 切换完成前不要启动正式 unit。
limactl shell --workdir=/ wecom-gateway-lab sudo systemctl stop wecom-agent-gateway-lab.service
# 停止/保留 VM，不删除持久证据。
limactl stop --tty=false wecom-gateway-lab
# 后续恢复同一 VM。
limactl start --tty=false wecom-gateway-lab
```
