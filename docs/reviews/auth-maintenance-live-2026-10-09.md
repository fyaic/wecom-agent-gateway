# 授权维护真实预续与交付 · 2026-10-09

本轮使用原 Gateway Bot、原专属 CLI profile，以及仅包含“发送消息”的私有配置。
没有创建 Bot、扩大权限、修改 Gateway 配置或安装常驻服务。

## 实测结果

| 环节           | 结果                                                                                |
| -------------- | ----------------------------------------------------------------------------------- |
| 初始业务查询   | 同 Bot `auth:probe` 通过，message-sessions 返回 3 条会话                            |
| 非目标桌面入口 | 企业微信当时停留在其他窗口，Keeper 无法定位目标页；不能称为任意桌面自动导航         |
| 恢复已知入口   | 主 Agent 通过桌面自动化切换目标 Bot 私聊；Keeper 从可见官方链接自行打开并核验权限页 |
| 预续前         | 消息权限有效至 10 月 15 日 16:44（上海时间），未过期                                |
| 真实预续       | 通过公开 worker 的 `once` 入口、真实 provider 和 Keeper 完成一轮，返回 `renewed`    |
| 预续后         | 页面与 Wrapper 均确认消息权限有效至 10 月 16 日 15:41，比原有效期推进 22 小时 57 分 |
| 重复周期       | 使用相同配置、状态目录和预续条件立即再运行，返回 `healthy`，未再次执行撤权预续      |
| 业务复验       | 独立 `auth:probe` 再次返回 identity=matched、message-sessions 验证通过、3 条会话    |

单次验收只在进程内显式启用维护、预续和 168 小时窗口，以覆盖仍有约 6 天有效期的真实权限。
持久环境文件保持默认关闭；没有伪造时钟、有效期或 GUI 结果，未跳过身份校验和耐久动作意图。
这验证的是**主动提前续期**，不是自然到期后的恢复，也不是无人值守跨周期认证。
Keeper 使用撤销后重新授予原权限的方式，可能产生短暂不可用窗口；不是官方 token 刷新 API。
邮件权限仍显示原有效期，未加入本轮白名单或操作范围。

`renewed` 的 `businessVerified=false` 有意保留：维护状态只证实页面结果，
业务证据来自独立只读探针，且仅覆盖消息会话查询，不扩展到所有办公能力或 SDK 聊天。

## 社区交付

- 中英文 README 与第三方声明明确引用 MIT 的 `fyaic/wecom-auth-keeper`，独立安装、独立进程，无源码内置。
- 提供可选 Aqua 用户会话 LaunchAgent 模板及加载、启停、日志和 GUI 前置说明；没有替用户自动安装。
- 子 Agent 复核维护状态机和 Wrapper，另一位补部署模板与测试；主 Agent 审查、实机执行及整合。
- 完整 CI：50 个测试文件、638 项测试通过，格式、类型及公开准备检查通过；LaunchAgent 模板通过 plist 语法检查。
- 发布审计发现此前三笔仅本地提交含非 noreply 邮箱。保留原分支，通过新的压缩交付提交避免把私人邮箱推到 GitHub；不改写远端历史。

## 仍然保留的缺口

1. 从任意桌面状态自动选择唯一 Bot 的可靠入口；目前需权限页已开或目标聊天中的链接可见。
2. 自然到期后的真实恢复，以及跨真实授权周期的常驻验证。
3. 其他办公能力各自的安全业务探针；不能用 message-sessions 成功代替。

上述缺口不阻碍可选插件的代码交付，但不支持“完全无人介入、任意机器开箱续期”的宣传。
