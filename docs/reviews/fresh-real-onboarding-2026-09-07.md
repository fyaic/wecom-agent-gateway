# 新目录真实接入验收 — 2026-09-07

## 范围与结论

维护者通过公开命令，在基线 `2275c0b` 的独立新 worktree 完成真实 Pi → 企业微信私聊接入，
包括首次注册、多轮记忆、主动通知和 Gateway 重启后续接。不是 Echo-only，也不是陌生用户调研。
没有复制生产 SQLite、授权名单或既有会话；安装复用了本机 pnpm 包缓存，不能冒充无缓存安装。
Bot 是已有授权测试 Bot，Pi 使用已安装、已认证的本机配置；不是新增 Bot 创建或模型开户验收。

## 实际操作

1. 新目录运行 `pnpm install --frozen-lockfile`：178 个包，全部来自本地缓存。
2. `pnpm demo`：六项通过，无 Bot 或模型调用。
3. `pnpm onboard --adapter pi`：生成私有最小配置与独立 workspace，未指定 provider/model 或演示扩展。
4. `pnpm agent:check`：真实两轮通过，均观察到文本增量、会话连续；两轮 4.402s / 2.560s，总计 7.682s。
5. 确认原服务无进行中任务、无投递积压后，停止其受管实例；既有 Bot 的两个凭据仅以子进程环境注入，
   未复制到新配置或提交。私有测试 launcher 只负责注入和日志投影，不替换公开注册/启动实现。
6. `pnpm enroll:direct`：桌面端在授权 Bot 私聊发送新的一次性口令；注册成功，未复用生产 ACL。
7. `pnpm start:checked`：12 项 Doctor 通过，官方 SDK 连接、Pi、Store 和本地控制面均 ready。
8. 经桌面端发送唯一标记的两轮文本：第一轮要求记住代号，第二轮不重复代号；客户端回答正确。
9. `pnpm proactive:send --target direct`：控制面报告 delivered，客户端看见对应通知。
10. 停止、重新启动该新 Gateway，发送第三轮不包含代号的提问；仍正确回答原代号。
11. 三轮分别使用显式 `--adapter=pi:rpc-v1` 的真实 ingress 验收：各匹配一条入站，九项检查全通过。
    最终 pending/leased/dead、active work 和媒体 spool 归零。测试实例停止后恢复原 macOS 服务。

测试 launcher 首次只向 pnpm 父进程发 TERM，未停止后代；发现后通过本项目监听端口确认精确 Gateway
进程并优雅停止，再改为独立进程组信号，后续停止成功。没有用宽泛进程匹配强杀其他服务。
这是测试 harness 的清理问题，不把未真正停止的父进程退出记作 Gateway 重启成功。
