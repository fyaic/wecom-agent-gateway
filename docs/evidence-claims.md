# 证据声明规范

本规范约束 README、路线图、发布说明、状态页和维护者交付用语，防止把局部实现或自动化测试误写为完整能力。

## 五级状态

| 状态           | 可以声明的内容                                                     | 不得外推                                             |
| -------------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| 已实现         | 代码路径存在，接口和 fail-closed 行为清楚                          | 不代表测试通过、客户端可见或生产可用                 |
| 自动化通过     | 指定 fixture、contract 或故障测试可重复通过                        | 不代表真实厂商 callback、网络、账号或客户端渲染通过  |
| 真实链路通过   | 记录日期、客户端/上游、Adapter、可见结果及清理/Outbox 状态         | 不代表其他客户端、Kernel、方向或故障路径通过         |
| 端到端认证完成 | 对应路线图退出条件全部满足，成功/失败/恢复路径都有真实及自动化证据 | 不得在仍有该能力 P0 退出项时使用“完整闭环”“全部完成” |
| 未完成/受阻    | 明确缺少的证据、依赖和安全降级                                     | 不得用相邻能力、模拟 fixture 或“应该可用”代替        |

## 声明规则

1. “支持”必须说明主体：Transport、Runtime Contract、具体 Adapter、真实客户端或完整产品。
2. capability 声明只证明代码会接受该类型；真实可用性必须由独立证据矩阵证明。
3. 厂商 callback fixture 不能替代真实 callback；SDK accepted 不能替代客户端可见或已读。
4. 媒体传输、媒体语义分类和 Agent 理解是三项不同能力，不能互相代替。
5. 只有对应路线图退出条件全部满足，才可写“完成”“闭环”或把检查项标为 `[x]`。
6. 失败结果也要记录：失败发生在哪一层、是否 fail closed、是否产生副作用、资源是否清理。
7. 对外 README 必须保留醒目的证据边界；发布前机器检查关键未完成项没有被删除或改写。

## 当前必须保留的公开限制

- 原生企业微信 `msgtype=video` 真实客户端 callback 尚未捕获。
- 当前 Pi Adapter 不支持视频理解；桌面 MP4 的语义分类和能力拒绝通过不等于视频问答通过。
- 引用/回复 callback 尚缺真实客户端验收。
- 宿主机物理断网、24 小时 Linux soak 和跨主机 active-active 尚未认证。
- Claude Code 仍是实验性 Adapter；真实 signed-out 诊断通过不等于认证成功路径通过。
