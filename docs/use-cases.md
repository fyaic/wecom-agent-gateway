# 日常怎么用：从痛点到可执行入口

[English](use-cases.en.md) · [先完成首次接入](getting-started.md)

下面是基于已实现链路的使用配方，不是对每个业务场景都做过实测的声明。
[真实案例台账](verified-kernel-cases.md)单独记录 Agent、版本、模态和证据。
Gateway 不包办模型、工具权限、定时调度或业务数据授权。

## 1. 不在电脑前，也能问自己的代码

**痛点：** 在路上被问到“这个行为在哪里控制”，不想远程桌面找文件。

首次配置时将 Codex / Kimi / Pi 的工作区指向项目；已有配置则修改相应工作区后重启。
在授权私聊里发：

> 在这个项目中，登录后跳转地址在哪里决定？请给文件名和关键逻辑，不修改任何文件。

再问：

> 如果没有配置回调地址，现在会发生什么？

**依赖：** Agent 本身能读取该目录。Codex 新手配置为只读，其他 Agent 的工具权限需自己确认。
这是在 Gateway 创建的会话里问答，**不是接管电脑上已开始的编程任务**。
不要让不可信的群成员通过 Agent 获得本地私有仓库访问权。

## 2. 手机截图直接排障

**痛点：** 错误截图在手机里，复制文字容易漏上下文。

向 Bot 发截图，再问：

> 看这张报错截图，先告诉我能确认的事实，再给三项排查步骤；看不清的地方请说明。

**依赖：** Adapter 与当前模型均支持图片。已有 Pi + 视觉模型、Codex、Kimi 等范围化图片记录；
不能从“文本能用”推导“当前模型一定看图”。Gateway 不会用虚构图片描述掩盖能力不足。
视频更不能直接套用：原生 video 真实回调仍待验收，传输成功也不保证 Agent 可解读视频。

## 3. 构建结束主动通知，不用反复刷新

**痛点：** 编译、测试、离线报告在电脑上跑，离开后不知道结束了没有。

先保持 Gateway 在线，确认只有一个授权私聊成员。
最小可执行示例（在 Gateway 仓库目录，跑本项目测试并通知结果）：

```bash
if pnpm test; then
  pnpm proactive:send --target direct --text 'Gateway 测试通过，可以查看结果了。'
else
  pnpm proactive:send --target direct --text 'Gateway 测试失败，请查看本地测试输出。'
fi
```

换成你的项目时，把测试命令换成实际任务，并在发送步骤切回 Gateway 目录，
或者明确配置控制 socket 路径。不要把敏感日志直接拼进消息。

**依赖：** 新手配置已开启本地控制面；`direct` 要求恰好一个授权成员。
CLI 不需要获得 Bot Secret。这里是任务主动调用发送能力，**不是内置 scheduler，也不是自动监视所有终端任务**。
跨机器 CI 不应直接暴露本地 socket；先设计受控连接。持久 Outbox 降低发送失败丢消息风险，不承诺“用户已读”。

## 4. 测试群里的项目问答入口

**痛点：** 团队重复问同一项目的问题，又不想每个人安装 Agent。

将 Bot 拉入允许的内部测试群，按[联调手册](real-wecom-runbook.md)明确群范围和成员 ACL，然后发：

> @Bot 根据当前工作区文档说明如何启动开发环境，只总结现有说明，不执行命令。

**依赖：** Bot 可见范围、群类型、@mention 和成员策略符合平台与项目要求。
不能保证外部群、上下游或任意组织用户可用。默认群会话上下文可能共享；
不要把“部署了 Bot”当成“完成了多租户数据隔离”，先从同权限的小组开始。

## 5. Agent 真需要你做选择时，在聊天里点一下

**痛点：** Agent 等待确认，你却不在终端旁边。

支持的 Agent 原生 ask-user 请求可映射成选择/确认卡片，点击后回到原任务；
不需要每条普通回复都出现“继续展开 / 总结要点”。

**依赖：** Adapter 的 interaction 能力与 Agent 自己的调用。可复现入口见
[Pi 原生交互示例](../examples/pi-wecom-interaction.mjs)和[卡片文档](interaction-cards.md)。
安装示例扩展、启用相应配置属于额外步骤；不是向任意模型说“给我卡片”就一定触发。
Gateway 只传递选择结果，不替 Agent 决定下一步业务逻辑。

## 6. 企业微信办公工具：在 IM 之外加一层工具

**痛点：** 问答完成后还要手工登记待办或查文档。

可让支持工具的 Agent 使用官方 [wecom-cli](https://github.com/WecomTeam/wecom-cli)，
例如先查询自己的待办，再根据明确指令创建一项。这需要 CLI 自身授权、对应工具绑定和必要的写操作审批。

**边界：** Gateway 不保证所有 Agent 默认都装好全部办公工具。
`wecom-cli` 是办公业务工具层，Bot SDK 是 IM 链路；两者不能混成“一个权限全部生效”。
先把普通聊天跑通，再按最小权限逐项加入工具。

## 暂时不适合直接承诺的场景

- 手机接管任意已运行桌面任务或跨 Kernel 迁移完整记忆。
- 任意视频直接理解、任意外部群可用。
- 无需部署机器与账号的托管服务。
- 多实例高可用或大规模多租户生产保证。

这些边界与未来工作见[状态](status.md)和[路线图](../ROADMAP.md)。
