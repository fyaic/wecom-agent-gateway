# 首次使用体验与社区入口审计

更新：2026-09-05。对应本轮目标：让用户理解项目、快速看见可信效果，并能区分接入链路与 Agent 前置条件。
本文是维护者工作记录，不替代[用户指南](getting-started.md)。

## 判断

项目的核心价值不是“另一个企微 AI Bot”，而是**复用一个 Bot 通信层，把自己已配置的 Agent 接进企微**。
现有实现有四类参考接入、外部 SDK 与持久投递基础，但“任意 harness 零配置开箱即用”不成立。
当前定位应是：**已有 Agent + 已有 Bot 的源码部署入口**，而不是托管产品或桌面任务遥控器。

## 本轮发现与修正

| 首次体验问题                                | 已实施                                                                    |
| ------------------------------------------- | ------------------------------------------------------------------------- |
| 首页先堆能力与工程验证，看不出日常用途      | 中英首页改为用户收益 → 真实 GIF → 快速开始 → Agent 差异 → 使用场景 → 边界 |
| 要先跑全量 CI、复制长配置，才能看到任何效果 | `pnpm demo`：不需账号的真实 Core / SQLite / 外部 Echo 加载链路            |
| 新用户需理解完整 `.env.example`             | `pnpm onboard`：五类最小配置、私有文件、独立 workspace、拒绝覆盖          |
| OpenClaw 最小示例遗漏必需认证               | 生成器与双语指南显式列出 token/password                                   |
| Agent 登录失败与企微失败混在一起            | `pnpm agent:check`：不连接 Bot 的两轮回答/会话检查，脱敏错误分类与超时    |
| 注册工具可能占用同一个 Bot，覆盖原成员名单  | 复用本机 owner lock；追加并去重 ACL；失败释放所有权                       |
| 卡片像默认“功能装饰”                        | 新手配置明确关闭回复动作与长任务控制卡；交互仅按需配置                    |
| 示例没有统一入口，历史文档压过使用指南      | docs 按任务导航，ADR 折叠但不移动；新增 examples 导航、模板说明           |
| 新用户反馈需要先理解协议                    | 新增独立上手卡点 Issue 表单，按安装/Agent/Bot/首条回复等阶段收集          |
| 跨 Agent 容易被理解成接管已有任务、迁移记忆 | 首页与指南明确独立会话、每进程一个 Adapter、无历史自动迁移                |

没有为营销效果改变 Core 语义、添加双身份、强制卡片或绕过 Agent 的认证与权限。
目录优化采用稳定路径和导航，不为“看起来整齐”大规模移动 package/ADR、破坏引用。

## 本轮可复核记录

本机 macOS，Node 26.3.1，pnpm 11.8.0；在隔离工作区从锁文件安装依赖，未复制生产 Bot 凭据。

| 验证                            | 实际结果                                                            | 不能推导什么                            |
| ------------------------------- | ------------------------------------------------------------------- | --------------------------------------- |

命令耗时是一次本机观察，Agent 的账号、模型和宿主状态会变化。
当前生产 Bot 未被替换、重新注册或为本轮演示重启。
本机全量 `pnpm run ci` 通过：35 个测试文件、265 项测试，格式、类型与公开文件/链接/隐私检查通过。
Linux CI 和 GitHub 渲染验收结果在本轮合并记录中补充。

## 后续优先级与退出条件

### 无缓存安装与真实 CLI 入口门（2026-09-05）

新增 `pnpm test:first-run`，只供维护者在一次性 checkout 中验收。它直接启动公开 pnpm 命令，
而非仅调用内部函数：demo 六项 → Echo 最小配置/权限/卡片默认值 → 缺 Bot 和 ACL 的 Doctor 拒绝 →
重复配置不覆盖 → 观测关闭时明确报告 disabled。子命令不继承 Bot/模型配置或 NODE_OPTIONS，
不执行模型、不连接企微；输出固定阶段和证据级别，不输出原始子进程日志。

已有 `.env`、`data` 或 `agent-workspace` 时在任何子命令前拒绝，悬空 `.env` 链接也拒绝。
成功后保留自己创建的空凭据配置与 workspace，便于查看；**不要在生产目录运行，也不自动清理或覆盖旧状态**。
这不是面向新用户的额外安装步骤，不进入 README 最短路径。

GitHub CI 新增 macOS/Linux 独立新 runner、Node 22、无依赖缓存、独立 pnpm store 的验收 job。
本机 macOS 的全新依赖 store 安装观察：178 个包、reused 0，安装 41.9s；上述五阶段通过。
这是单次网络/宿主观察，不是时延承诺。两个远端平台的结果以对应 PR 中 `Fresh install` job 为准。

边界：验证源码安装与无凭据安全失败，不含真实 Agent 认证、Bot 注册、客户端首聊或 24h soak。
后者仍需分别记录；不能将 CI 的空凭据路径写成“新用户全流程已认证”。

### 后续
